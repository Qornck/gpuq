# 断电及进程失联恢复

在 daemon 使用的 TOML 中设置 `max_orphan_retries = 3`，启用每个任务最多三次失联自动重新入队；默认0保持原行为。计数独立于OOM重试和总attempt，持久保存在SQLite `orphan_recoveries` 表，daemon重启不清零。

仅恢复starting/running且runner、worker均消失的任务。Linux下数据库更新时间早于系统启动时刻的记录视为前一次启动遗留，避免重启后PID复用导致误判存活。取消请求、已完成或普通失败任务不会重新入队。状态更新与恢复审计在一个事务中完成，避免依赖任务见到中间failed状态。达到上限仍标记orphaned失败，需人工检查。

保留同一ID、命令、环境、依赖、优先级、资源约束及显存学习结果，重新进入正常调度，不绕过exclusive或稳定采样。不会追溯重试已有failed任务。日志打印自动恢复ID；SQL表保留恢复次数、时间及此前attempt。

gpuq只负责重新启动命令；训练脚本必须自己实现模型、optimizer、调度与随机状态恢复。没有断点支持的程序会从头执行，所以仅应在任务可安全重入的个人队列启用。未保存的轮次可能重算。临时systemd结果监控不属于gpuq任务，此设置不使其自动开机启动。

CPU测试通过模拟失联、PID复用、存活worker、取消、终态竞争、重试上限与资源保持验证；不以真实服务器断电作为测试。时钟显著回拨可能影响基于系统启动时间的识别。
